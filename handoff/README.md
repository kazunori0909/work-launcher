# handoff — Mac と Windows のやりとり

片方の OS でしか確かめられないことを、もう片方の Claude に頼むための置き場所。
作業中のブランチに置き、git の pull / push で受け渡す。

## 自分はどちらか

`process.platform`（シェルなら `uname` が `Darwin` か、Windows か）で決める。

- Mac … `mac`
- Windows … `win`

## ファイル

- 1依頼 = 1ファイル。名前は `<YYYYMMDD-HHMM>-<from>-to-<to>-<要件>.md`
  （例: `20261121-1544-mac-to-win-git-pattern.md`）。日時は依頼を書いた側の時刻
- 中身は下の雛形。回答は同じファイルの末尾に書く（1ファイルで1往復が読める）
- 追いの依頼は新しいファイルにする（前のファイルの名前を「関連」に書く）

```markdown
# <要件>

- from: mac
- to: win
- 状態: 依頼中
- ブランチ: <ブランチ名>
- 関連: （前のファイルや PLAN.md の節。無ければ省く）

## 依頼

### 背景

### やってほしいこと

1. …

### 返してほしいもの

## 回答

（受けた側が書く）
```

## 状態の移り方

| 状態     | だれが     | すること                 |
| -------- | ---------- | ------------------------ |
| 依頼中   | 依頼する側 | ファイルを作り push する |
| 回答済み | 受ける側   | 「回答」を書き push する |
| （削除） | 依頼する側 | 要点を docs へ移し、消す |

- 途中で進められないとき、受ける側は状態を `保留` にし、理由を「回答」に書いて push する

## 受ける側の手順

1. `git pull` し、`handoff/` で **to が自分** かつ **状態が依頼中** のファイルを探す（古い日時から）
2. 「やってほしいこと」を実行する。依頼に無い変更（コードの修正・コミット）はしない。
   直した方がよいと気づいたら「回答」に書く
3. 「回答」を書き、状態を `回答済み` にする
4. `handoff/` だけをコミットして push する（件名は `handoff: <要件>（回答）`）

## 決まり

- commit・push はユーザーに言われたときだけ（CLAUDE.md）。「handoff を処理して」「依頼を出して」と言われたら、
  `handoff/` だけの commit・push までを頼まれたものとする
- 個人情報（ユーザー名を含むパス・メールアドレスなど）は書かない。パスは `%USERPROFILE%`・`~` などに置き換える
- 出力は必要な行だけ貼る。長いものは要点を書く
- PR をマージする前に、そのブランチの依頼ファイルが残っていないことを確かめる（README.md だけ残す）
