# Phase 25: 多言語対応（ja / en）

## 課題

画面・エラー・Info・ヘルプの文言がすべて日本語で書かれている。
日本と海外で共同で進める案件では英語でも使いたい。ただし、メンテナンスの手間は小さく抑えたい。

文字列の性質は3種類ある。

- システムの短い文言（ボタン、エラー、Info の表示。`core/load`・`runner.ts`・`info.ts` など）
- ヘルプの本文（`help/sections/*.tsx`・`examples.ts`）
- ユーザーが書く設定（`title`・`label`・`tooltip`・`confirm`、`md` / `html`）

## 方針

3種類を別のやり方で扱う。**このフェーズでは 1・2 と「言語の決め方」を行う**。3 は別フェーズにする（docs/README.md の「次に扱う候補」）。

1. **システムの文言は、キーで引く辞書にする**。`src/core/i18n/` に `ja.ts`（正）と `en.ts` を置く。
   `en` の型を `ja` に合わせ、訳し忘れを型エラーにする。引数つきの文言は関数にする。
   ライブラリ（i18next など）は入れない。core に置き、Electron に依存させない
2. **ヘルプは、章ごとに言語別のファイルにする**（`sections/ja/` と `sections/en/`）。
   全部の章に両方の言語があるかをテストで確かめる（そろえる前提なので、ja に戻す仕組みは作らない）。`examples.ts` も言語ごとに持ち、既存のテストを両方の言語で回す
3. **ユーザーの設定の文字の項目は「文字列か、言語の表」で書けるようにする**（`label: { ja: デプロイ, en: Deploy }`）。
   探す順は、表示中の言語 → `config.yaml` の `lang`（案件の既定）→ 表の最初。
   `md` / `html` のファイルは、`setup.en.md` があればそれを読む。関数には `ctx.lang` を渡す。
   読み込み時に文字列へ変えるので、画面側は変えない

### 言語の決め方

1. ウィンドウ右上のボタン（いまの言語を出し、押すたびに次の言語へ）で選んだ言語。userData の `settings.json` に記憶する
2. 選んでいなければ OS の言語（`app.getLocale()`。ja でなければ en）

- 記憶はアプリ全体で1つにする（案件ごとにしない）
- 切り替えたら、開いている全部のウィンドウをすぐ描き直す
- コンソールはすでに出た行を書き換えない。切り替えた後に出る行から新しい言語になる

## 決定事項ログ

### 2026-11-22: 文字列の性質ごとに扱いを分ける

- システムの文言は型つきの辞書、ヘルプは言語別のファイル、ユーザーの設定は「文字列か、言語の表」にする（方針の 1〜3）
- 理由: ヘルプは文中に `<code>` が混ざる長い文章で、1文ずつキーにすると読みにくく直しにくい。ユーザーの設定は一部だけ訳しても壊れない形にし、ベストエフォートで訳せるようにする
- 採らなかった案: ユーザーの訳を、gettext のように元の文言をキーにした別ファイルに置く案。元の文言を直すと訳が黙って外れ、気づきにくい
- 3つは別フェーズにする。このフェーズは 1 と言語の決め方

### 2026-11-22: 言語は右上のボタンで切り替え、アプリ全体で記憶する

- 既定は OS の言語に従う。右上の `ja` / `en` でいつでも切り替えられ、選んだ言語を記憶する（ユーザーの提案）
- `config.local.yaml` に `lang` を書く案はやめた。右上のボタンと役目が重なるため
- コンソールの出力済みの行はすぐには切り替えなくてよい（ユーザーの判断）

### 2026-11-22: 切り替えはボタン1つにする

- `ja` / `en` の2つのラベルをやめ、いまの言語を出すボタン1つにした。押すたびに次の言語に変わる（ユーザーの指示）
- 言語が増えても順に回せばよい。ツールチップに切り替え先を出す

### 2026-11-22: ヘルプの英語（方針 2）もこのフェーズに入れる

- 最初は別フェーズにしていたが、アプリ側の文言と合わせて済ませる（ユーザーの判断）
- ユーザー設定の言語の表（方針 3）は、引き続き別フェーズ

### 2026-11-22: 実装の形

- core に「いまの言語」を1つ持ち、`t()` で辞書を引く。辞書を関数の引数で回さずに済む。メイン・画面・scriptHost（`CallRequest.lang` で受ける）はプロセスごとに `setLang` する
- 画面へは `ProjectView.lang` で伝える。切り替えたらメインが全部のウィンドウを読み直すので、読み込みのエラーも新しい言語で作り直す。Info は `key` で取り直す
- 訳すのはアプリが作る文言だけ。OS から取った値（ボリューム名など）はそのまま。Mac の `/` に付ける「起動ディスク」はアプリが付ける名前なので訳す
- 残したもの: `builtinTools.ts` の `help`（ヘルプのフェーズで扱う）、`openFolder.ts` の osascript の中の文言、`assertNever` の内部エラー
- ヘルプの章の一覧（ID・分類・タイトル・本文）は `sections/<言語>/index.ts` に1つずつ置く。章の枠と見出しは HelpPage が付け、タイトルを一覧と本文の2か所に書かない
- ヘルプの部品の短い文言（早見表の見出し・アイコン検索など）は辞書の `help`。組み込みのツールの説明は、言語で変わるものだけ `help: { ja, en }` と書く
