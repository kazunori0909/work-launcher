# Phase 27: フェーズ記録を archive に移す

## 課題

- 完了したフェーズのフォルダが 26 個（約 3,000 行）残っていて、圧縮は一度もしていない
- 今の `/phase-compress` では、決定事項を `phases.md` にフェーズ順で足していくだけになる。後のフェーズで覆った決定も残るので、いま有効な決定を知るには複数の節を読み比べる必要がある
- 元の記録はフォルダを消すと git 履歴にしか残らず、遡りにくい

## 方針

- 文書を3つの役割に分ける
  - **いまの正**: `config.md`、新しく作る `design.md`、`knowledge.md`。トピックごとに書き、変わったら追記せず書き換える
  - **当時の記録**: `docs/archive/phase<N>-<slug>/`。フォルダを要約せずに `git mv` で移し、移したあとは編集しない
  - **索引**: `docs/README.md` の表
- `design.md`・`knowledge.md` の項目には「由来: Phase N」として archive へのリンクを付ける
- archive は経緯を遡るときだけ開く。普段は読まず、grep の対象からも外す
- `/phase-compress` は「いまの正への反映（ユーザーが承認する）」と「archive への移動」の2段にする。要約しなくなるので、名前は `/phase-close` に変える
- `knowledge.md` も `design.md` と同じく、トピックごとに少しずつ育てる。当面は archive の KNOWLEDGE.md を直接指す
- archive から外へのリンク（`../config.md` の2つ）だけは、移すときに `../../` に直す

## 決定事項ログ

### 2026-11-22: いまの正と当時の記録を分け、記録は archive に要約せずに移す（ユーザーが承認）

- 編集しない記録なら、古い記述が残っていても不整合にはならない。不整合が問題になるのは、更新を続ける文書の中だけ
- 要約しないので、圧縮の手間と承認する量が減り、要約で情報が落ちることもない
- 採らなかった案:
  - 今のスキルのまま `phases.md` に追記していく案。覆った決定が積み重なっていく
  - フォルダを消して git 履歴だけに残す案。記録を遡りにくい

### 2026-11-22: `design.md` は少しずつ育て、`phases.md` は作らない（ユーザーの判断）

- `design.md` は、今回は雛形とトピックの見出しだけを作る。以降のフェーズでそのトピックに触れたときに、archive から理由を拾って書く。全フェーズを一度に読むと手間がかかり、承認する量も多くなる
- `phases.md` は作らない。索引は README の表、当時の記録は archive、いまの正は `design.md` が受け持つので、`phases.md` を作ると同じことを3箇所に書くことになる
