# Phase 24: ヘルプから config.local.yaml の雛形を作る

## 課題

- `config.local.yaml` を初めて作るのが難しい。どこに置き、何を書けば効くのかが分かりにくい

## 方針

- ヘルプ（「設定ファイルの編集」の「自分だけの設定」）にボタンを置き、押すと `launcher/config.local.yaml` を作る
- **新規作成のみ**。既にファイルがあるときは作らず、その旨を出す（上書き事故を防ぐため、作り直したいときはユーザー自身が消す）
- 中身は、重ね方の例がそのまま動いて見えるものにする
  - ページの書き換え: 実行時の config.yaml の**最初のページ**の ID に、md で
    「このメッセージは、config.local.yaml から追加しています」を足す
  - Info のツールの表示を git だけにする: 実行時の config.yaml の git 以外のツールを `hidden: true` で並べる
    （案件に git が無ければ `- git` を書き、足す例も兼ねる）
  - 新しいページを足す
- ローカル設定の `info.tools` に `hidden: true` を書けるようにする。同名は上書きなので、案件のツールを消せる

  ```yaml
  info:
    tools:
      - { name: node, hidden: true } # 案件のツールを表示しない
      - { name: mytool, command: mytool --version } # 自分だけのツールを足す
  ```

- ファイルの中身（YAML の文字列）を作る処理は Electron に依存させず `src/core/` に置き、vitest でテストする

## 決定事項ログ

### 2026-11-21: ヘルプのボタンで新規作成だけを行う（ユーザー判断）

- 既存ファイルがあるときは上書きしない。消すのはユーザー自身に任せ、事故を減らす
- 中身はページの書き換え（最初のページに md）・Info のツールを git だけ・新規ページの3つ

### 2026-11-21: Info のツールは「足す」と「表示しない」だけにする（ユーザー判断）

- 使い方は「開発者向けのツールは要らないので消す（例: プロデューサー）」と「自分だけ使うツールを足す」。
  全部消してから足す使い方は無いと考える
- いまの合成（後ろに追加・同名は上書き）は変えず、ツールの項目に `hidden: true` を足す。互換は崩れない
- 採らなかった案: info に `replace: true`（丸ごと置き換え。用途が無い）／ローカルの `tools` で丸ごと置き換え
  （足すだけの使い方ができなくなり、互換も崩れる）／`env`・`registry` にも `hidden`（いまは要望が無い）
