# 日本語の文章の書き方

**アプリの文言・ヘルプ・Web サイト・docs・コミットメッセージに共通の、日本語の書き方。**
全文は読まず、見出しで検索して節だけ読む。英語の文言は、日本語と同じ内容を英語として自然に書く（直訳しない）。

拠り所は末尾の「出典」。このリポジトリで決めたこと（出典と違うものを含む）は「このリポジトリの決まり」と書く。

## 文を組み立てる

- **一文に一つのことを書く。** 長い文は句点や接続詞で分ける。60字を超えたら分けられないか見直す（公用文作成の考え方）
- 接続助詞の「が」（「〜ですが、〜」）や、連用中止（「〜し、〜し、」）を続けない
- 「の」「に」「て」などの同じ助詞を続けない（「設定の画面のボタンの色」→「設定画面にあるボタンの色」）
- 主語と述語、修飾語と被修飾語は近くに置く。長い修飾節は前に出すか、文を分ける
- 結論を先に書き、理由や条件はあとに書く
- 二重否定を避ける（「〜しないと使えない」→「使うには〜する」）
- 伝えることを絞る。量が増えると分かりやすさが落ちる

## 言葉を選ぶ

- 漢語より和語・訓読みの動詞を選ぶ（「実施する」→「行う」、「確認する」→「確かめる」、「削除する」→「消す」）
- 専門用語は、言い換えるか、初出で説明を添える。読む人が使ったことのない概念を前提にしない
  （例: 英語では「日本語のまま書ける」は伝わらないので、「エンコードが要らない」と書く）
- 同じものは同じ言葉で呼ぶ。言い換えると別のものに読める
- **このリポジトリの決まり**: ソフトの version は「バージョン」と書く（「版」は使わない）。長くなるときは「Ver.」

## 表記

- 句読点は全角の「、」「。」。かっこは全角の（）「」（コードや英文の中は半角）
- 英数字は半角。記号は和文の中では全角（：・→ など）、コードや英文の中では半角
- 数字と助数詞の間にはスペースを入れない（1つ・2通り・3行）
- 「版」は、種類を表すとき（ポータブル版・インストール版）だけ使う。version の意味では「バージョン」
- カタカナ語の語尾の長音は省かない（サーバー・ユーザー・フォルダー※）
  - ※ このリポジトリでは既存の文言に合わせて「フォルダ」と書く
- 補助動詞・形式名詞・副詞の多くはひらがなにする（〜してください・〜できる・こと・とき・ところ・すでに・まだ）
- **このリポジトリの決まり: 和欧間に半角スペースを入れる**（「YAML を置く」「Windows で動く」）。
  JTF は入れない立場だが、ここでは既存のすべての文言がスペースありで揃っているため、こちらに合わせる。
  ただし、全角のかっこ・句読点の隣には入れない（「（YAML）」「YAML、」）

## 文体

- アプリのヘルプ・Web サイトの本文は「です・ます」
- 見出し・ボタン・ラベル・表のセル・キャプションは体言止めか常体にし、句点を付けない。
  ただし、キャプションが複数の文になるときは句点を付ける
- docs（PLAN.md など）・コードのコメントは常体（「〜する」「〜だ」）。体言止めも使う

## 画面での改行

日本語は単語の間に空白が無いので、何もしないとブラウザは文字のどこでも折り返す。
英語のように単語の途中で折れないのとは違い、「ボタ|ン」のように意味の途中で切れて読みにくくなる。

**短い文と本文で扱いを分ける。**

| 対象                                   | 折り方                                   |
| -------------------------------------- | ---------------------------------------- |
| 見出し・リード文・カード・キャプション | 文節で折る（入りきらない文は次の行から） |
| ボタン・表のセル・サイドメニュー       | 文節で折る                               |
| 本文の段落                             | 普通に折る（行頭の句読点と孤立だけ防ぐ） |

本文まで文節で折ると、行の右端がガタガタになり、段落の中に妙な空きができて、かえって読みにくい。

### やり方

- **`lang` を付ける。** `word-break: auto-phrase` は `lang="ja"` が無いと何もしない（祖先の要素に付いていればよい）
- **文節で折る（確実な方法）**: BudouX で文節の境目に `<wbr>` を入れ、`word-break: keep-all; overflow-wrap: anywhere;` で他の位置では折らない。
  Web サイトでは、Web だけの文言にビルド時に当てている（`site/src/phrase.ts`）
- **文節で折る（CSS だけ）**: `word-break: auto-phrase`。効くのは Chrome / Edge だけ（2026-11 時点。Safari・Firefox は普通に折れる）。
  React で描くヘルプの見出し・表はこれにしている（アプリは Electron なので必ず効く）
- **文の途中で行を変えない**: 文ごとに `display: inline-block` の要素で包むと、入りきらない文は次の行から始まる（`site/src/phrase.ts` の `.s-sentence`、ヘルプのアラートの `.help-sentence`）
- **行の長さを揃える**: 中央揃えの見出し・リード文は `text-wrap: balance`、左揃えの本文は `text-wrap: pretty`
- **行頭の句読点を防ぐ**: `line-break: strict`
- 文節を `<span>` で包むときは、その親に `display: flex` を当てない（1文字ずつ割れることがある）
- `<br>` で位置を決め打ちしない。画面の幅が変わると、かえって変な位置で切れる。
  どうしても分けたい見出しは、行ごとに要素を分ける（Web サイトのトップの見出しのように）

### 文言を書くときにできること

- 見出し・ボタンは短くする。折り返さない長さが一番よい
- 一つの文を短くすると、文単位で行を変えやすくなる
- 英語は単語の間で折れるので、特別なことはしない（`text-wrap` だけ当てる）

## ヘルプのアラートと折りたたみ

**このリポジトリの決まり。** ヘルプの章では `Callout`（アラート）と `Fold`（折りたたみ）を使う（`help/parts.tsx`）。
使いすぎると目立たなくなるので、種類と数に上限を置く（由来: [Phase 38](archive/phase38-help-alerts-details/PLAN.md)）。

アラート:

- 使うのは3種類だけ
  - `warning` … 読み飛ばすと動かない・意図と違う動きになること。とくにエラーが出ずに気づきにくいもの
  - `note` … OS などの条件で動きが変わること（「Windows だけ」など）
  - `tip` … 知っていると手間が減る別のやり方
- `important`・`caution` は使わない。前者は本文に書けば足り、後者（取り返しがつかない操作）はヘルプに当たる内容が無い
- 1つの節（h3）に1つまで、1つの章に3つまで。アラートを続けて置かない
- 中身は1〜3文。コード見本や表は入れず、外に置く
- 本文の流れで読めば足りる補足や、表の言い換えはアラートにしない
- 日本語は文の切れ目で行が変わる（`Callout` が「。」で分けて `.help-sentence` で包む。→「画面での改行」）。
  1文が1行に収まる長さにし、括弧の補足は別の文にする。文ごとに行を変えたせいで、包まないときより行が増えないようにする
  （短い文・長い文・短い文の並びは増えやすいので、まとめる）

折りたたみ:

- 畳むのは、特定の状況でだけ要る内容（例外の対処・上書きのしかた・細かい数え方）
- 本筋の手順・早見表・最初の見本は畳まない。節の見出し（h3）も中に入れない
- 見出しは「〜とき」「〜の数え方」のように、読む人が自分に要るかを決められる言葉にする
- 1つの折りたたみには1つの話題だけを入れる

## ソースの中での改行

表示ではなく、ファイルの中で行を変えるときの注意。

- **Markdown（docs）**: 段落の途中の改行は、多くのブラウザ（Chrome など）で半角スペースとして出る。
  改行するなら、文の終わり（「。」のあと）か、半角スペースが入ってもよい位置（英数字やコードの前後）にする。
  一行に一つの文を書くと、差分も読みやすい
- **JSX（ヘルプの章）**: 文字の途中の改行は、コンパイルで半角スペースになる。
  Prettier は空白の位置でしか折り返さないので、日本語の途中では切れない。
  手で改行するときも、半角スペースが入ってよい位置にする（`{' '}` で明示されているところ）
  「、」「。」のあとで行を変えると「、 」のように空白が出るので、そこでは行を変えない
