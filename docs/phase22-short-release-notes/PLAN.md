# Phase 22: リリースノートを短くする

## 課題

- Release の冒頭の案内（`.github/release-notes.md`）が34行あり、毎回長い
- サンプルの使い方・Mac の見分け方・ハッシュと attestation の確かめ方は、README にも同じことが書いてある

## 方針

- 冒頭には、ファイルと対象の表と、初回起動の警告・README へのリンクの1文だけを置く
- 詳しい手順は README（「インストール」「ダウンロードしたファイルを確かめる」）に任せる

## 決定事項ログ

### 2026-11-21: リリースノートの冒頭を表とリンクだけにする（ユーザー判断）

- 表は残す。GitHub が消せない「Source code」を付けるため、どれを落とすかの案内は要る（→ phase8 の 2026-11-14）
- 初回起動の警告は、落とした直後に必ず当たるので1文だけ残す
- それ以外は README と重なるので消す。2箇所に書くと片方が古くなる
