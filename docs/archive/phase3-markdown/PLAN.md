# Phase 3: Markdown の表示

## 課題

- 設定に手順や注意書きを書けない。ボタンの近くに説明を置きたい

## 方針

### 範囲

- 入れる: 埋め込みの `markdown`・`mdfile`・`html`（[docs/config.md](../../config.md) 3.4）、
  組み込みのヘルプを章立て（左に一覧、右に本文）にする

### 構成

- リンク・画像のパスの解決と見出しの取り出しは `src/core/markdown.ts`（Electron 非依存、単体テスト付き）
- md の読み込み（mdfile）はメインで行い、設定と一緒に画面へ渡す。読んだファイルは変更を見張る

## 決定事項ログ

### 2026-11-13: 描画ライブラリ・html の扱い・マニュアルの並べ方

- Markdown は react-markdown + remark-gfm で描く。React の要素として描くため md 内の生の HTML は既定で描かれず、
  リンク・画像の扱いを部品ごとに差し替えやすい。案: marked / markdown-it は HTML 文字列を差し込む方式で、
  リンク・画像の扱いを変換後の HTML で直すことになる（ユーザー判断）
- 埋め込みの `html` もこのフェーズで入れる。埋め込み系がそろうため（ユーザー判断）
- マニュアルページは左にファイルの一覧、右に本文を1つずつ出す。一覧はファイル名の順で、
  各 md の最初の見出しを名前にする。案: 全部を縦につなげて目次を置く（ユーザー判断）

### 2026-11-14: HTML・リンク・画像の扱い（Claude 提案、ユーザーへ報告済み）

- md 内の生の HTML は描く。rehype-raw で HTML として読み、rehype-sanitize（GitHub と同じ規則）で
  危険な部分を取り除く。見た目を整えられるよう `class`・`style` 属性は残す。`<details>` などを使いたい場面があるため
- `html` 項目は DOMPurify で取り除く。加えて `<form>`（送信で画面が移る）と `<style>`（画面全体に効く）も取り除く。
  画面の CSP（`script-src 'self'`）が二重の守りになる
- リンクの行き先は3つ。`http`・`https`・`mailto` はブラウザ、`.launcher/manual/` の md はマニュアルページ、
  それ以外のファイルは OS の既定アプリ（`open` と同じ）。ほかのスキーム（`javascript:`・`file:` など）は開かない。
  画面が移ってしまわないよう、メインでも `will-navigate` を止める
- 画像は専用のプロトコル `wl-file://project/<projectDir からの相対パス>` で渡す。案件フォルダの外は返さない。
  開発時の画面は http から読むため `file://` は使えず、使えたとしても任意のファイルが読めてしまうため。
  `https` の画像（バッジなど）も表示する（CSP の `img-src` に足した）
- 見出しに GitHub と同じ id を振る（rehype-slug）。マニュアルで `#見出し` のリンクを使うため。
  id は取り除いた後に振る（rehype-sanitize が id に `user-content-` を付けるのを避ける）
- mdfile とマニュアルフォルダも変更を見張る。フォルダは `fs.watchFile` で更新日時を見て、md の追加・削除に気づく

### 2026-11-14: マニュアルページをやめ、ヘルプを章立てにする

- `.launcher/manual/*.md` を並べるマニュアルページは作らない（入れてみて、不要と判断。ユーザー判断）。
  案件の説明は `markdown`・`mdfile` でページに書ける。予約 ID `manual` も外した
- 代わりに組み込みのヘルプを、マニュアルページで作った「左に一覧、右に本文」の形にする（ユーザー判断）。
  章を1つずつ出し、選んでいた章はタブを移っても残す
- 設定に書いた `help` ページの項目は、ヘルプの最初の章「この案件」に出す（Claude 提案）。
  案: 全章の後ろに足す方法は、章立てにすると置き場所が無くなるため採らない
- 上の決定事項のうち、マニュアルページの並べ方とマニュアルへのリンクの扱いは無効になった

### 2026-11-14: 種類ごとの既定のアイコン

- `icon` を省いたら種類ごとの既定を出す。実行系は `terminal`、`url` は `globe`（ユーザー判断）。
  `open` は拡張子があれば `file`、無ければ `folder-open`、`function` は `code`（Claude 提案）
- `icon: ""` でアイコンを出さない（既定を付けたため、消す手段を残す）
- 既定の `label` は、bat と sh を併記したときにその OS で実行する方の1行目を使う
  （それまでは書いた順の先頭で、Mac でも bat の本文が出ていた）
