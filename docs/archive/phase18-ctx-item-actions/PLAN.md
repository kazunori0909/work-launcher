# Phase 18: 関数から項目の動作を呼ぶ

## 課題

- function の中からは `ctx.open`・`ctx.openUrl` しか呼べない。Office を開く・bat などを動かすには、
  Node の `child_process` で自前に書くことになり、YAML の項目と挙動（読み取り専用・文字コード・コンソールへの出力）が揃わない
- 押したときの処理を YAML に直接書く種類キー（`click` など）は足さない。処理は JS ファイルに置く
  - 理由: YAML の中の JS はエディタの支援・lint が効かず、エラーの行が追えない。`${...}` が設定の変数と JS でぶつかる。
    別の項目やイベントから使い回せない

## 方針

### 呼び方

- `ctx` に、YAML の種類キーと同じ名前の関数を足す。別の入れ物（`button.` など）は作らない

  | YAML                                   | 関数内                                         |
  | -------------------------------------- | ---------------------------------------------- |
  | `open`                                 | `ctx.open(path)`                               |
  | `url`                                  | `ctx.url(url, { params })`                     |
  | `excel` / `powerpoint` / `word`        | `ctx.excel(path, { readonly })` など           |
  | `bat` / `sh` / `powershell` / `python` | `ctx.bat(script, { cwd, env, encoding })` など |

- 渡せるのは動作に関わるキーだけ。`label`・`icon`・`tooltip`・`confirm` は受け取らない（知らないキーはエラーにする）
- 文字列の `${workDir}`・`${select:ID}` などは YAML と同じく展開する
- `bat` と `sh` の併記にあたるものは作らない。関数の中で `process.platform` を見て分ければ足りる。
  その OS で動かせない種類を呼んだらエラーにする

### 終わりを待つ

- どれも Promise を返す。失敗したら reject する（待たなければ、これまでどおりコンソールにエラーを出すだけ）
- 実行系は終わるまで待ち、終了コードを返す。出力は YAML の実行系と同じくコンソールに流す
- 実行系には「待たずに始めるだけ」の指定 `wait: false` を置く
- 待った実行系は、出力を `stdout`・`stderr` に分けて結果に入れる。受け取るかどうかの指定は作らない
  （常に入れれば足り、キーが1つ減る）
- `console: false` で、その実行をコンソールに出さない。出力を関数で読み、出す文を自分で決めるため
- 失敗の伝え方: 本体はコンソールに出さず、関数側で reject する。`await` していない reject は
  `unhandledRejection` で拾い、コンソールにエラーを出して関数は続ける（`await` していれば関数の例外として1回だけ出る）
  - 案: 本体がいつもコンソールに出す方法は採らない。`await` していると同じエラーが2回出るため
- 関数は、頼んだ動作の結果がすべて返るまで終わらせない（終わった直後にプロセスを止めると、最後の失敗を出せないため）
- 関数から始めた実行は、押した項目と結び付けない（ボタンは実行中の表示にならない）。関数が終わっても動かし続け、
  ウィンドウを閉じたときに止める

- 実行系の本文は、前後の空行と共通のインデントを取り除いてから動かす（YAML の `|` と同じ形）。
  関数の中でバッククォートをインデントして書くと、python が IndentationError になり、
  先頭の改行はコンソールに空のプロンプト行を出すため（→ KNOWLEDGE.md）
- bat のエコーは消さない（YAML の bat と同じにする）。出力を読むときは `@echo off` を書くよう、ヘルプに載せる
  - 案: `console: false` のときだけ `@echo off` を自動で足す方法は採らない。同じ本文で出力が変わり、分かりにくい

## 決定事項ログ

### 2026-11-16: YAML に処理を直接書く種類キーは足さない（ユーザー判断）

- 理由は「課題」のとおり。処理は JS ファイルに書くことを基本にする

### 2026-11-16: `ctx.openUrl` は `ctx.url` に置き換える（ユーザー判断）

- 公開済みだが、使っているのは内部だけ。互換のための別名は残さない

### 2026-11-16: 実行系は終了を待つ。待たない指定も置く（ユーザー判断）

- 続けて次の処理を書けるようにするため。起動するだけで先へ進みたい場面のために、待たない指定を足す

### 2026-11-16: 実行系に `console: false` と、出力の受け取りを足す（ユーザー判断）

- コンソールに出す・出さないを選べるようにする
- stdout と stderr を分けて受け取り、成功・失敗で出す文を使い分けられるようにする

### 2026-11-16: 実行系の `cwd` を省いたら、関数の作業フォルダで動かす（ユーザー判断）

- 同じページの YAML の実行系と同じフォルダになり、関数の中の Node の相対パスとも食い違わない
- 相対の `cwd` は YAML と同じく launcherDir 起点
  - 案: いつも launcherDir にする方法は採らない。ページに `cwd` を書いた案件で、YAML のボタンと動くフォルダが分かれる
  - 案: `cwd` を必須にする方法は採らない。YAML では省けるのに関数では省けない差が出る
