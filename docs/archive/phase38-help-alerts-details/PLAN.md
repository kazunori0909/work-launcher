# Phase 38: ヘルプにアラートと折りたたみを使う

## 課題

- ヘルプの章は段落が続くだけで、読み飛ばすと失敗する注意と、ふつうの説明の見分けが付きにくい
- 一部の人にしか要らない細部が本筋の間に挟まり、章が長く見える
- Phase 37 で足したアラートと折りたたみを、ヘルプにも使って見やすくしたい。ただし使いすぎない

## 方針

ヘルプ用の部品 `Callout`（アラート）と `Fold`（折りたたみ）を `help/parts.tsx` に足す。
見た目は設定の項目（note などの項目・details）と同じにする。使い方は次のルールに沿う。

### アラートのルール

- 使うのは3種類だけ
  - `warning` … 読み飛ばすと動かない・意図と違う動きになること。とくにエラーが出ずに気づきにくいもの
  - `note` … OS などの条件で動きが変わること（「Windows だけ」など）
  - `tip` … 知っていると手間が減る別のやり方
- `important`・`caution` は使わない。前者は本文に書けば足り、後者（取り返しがつかない操作）はヘルプに当たる内容が無い
- 1つの節（h3）に1つまで、1つの章に3つまで。アラートを続けて置かない
- 中身は1〜3文。コード見本や表は入れず、外に置く
- 日本語は文ごとに `inline-block` で包み、入りきらない文を次の行から始める（`Callout` が「。」で分けて自動で包む）。
  1文が1行に収まる長さにし、括弧の補足は別の文にする。文ごとに行を変えたせいで、包まないときより行が増えないようにする
- 本文の流れで読めば足りる補足や、表の言い換えはアラートにしない

### 折りたたみのルール

- 畳むのは、特定の状況でだけ要る内容（例外の対処・上書きのしかた・細かい数え方）
- 本筋の手順・早見表・最初の見本は畳まない。節の見出し（h3）も中に入れない
- 見出しは「〜とき」「〜の数え方」のように、読む人が自分に要るかを決められる言葉にする
- 1つの折りたたみには1つの話題だけを入れる

### 構成の手直し

- アラートや折りたたみに移すとき、話題に合わない節に置かれていた段落は合う節へ動かす
  （Info のレジストリの引用符、関数の cwd と OS の段落など）

## 決定事項ログ

### 2026-11-26: アラートと折りたたみの使い方

- 上の「アラートのルール」「折りたたみのルール」で使う。過剰に使わないことを優先し、種類と数に上限を置く
- 文章の構成は変えてよい（ユーザーの許可）

### 2026-11-26: アラートの中は文の切れ目で行を変える

- 「入れてください。」のような文の切れ目で行が変わるほうが読みやすい（ユーザーの指摘）
- `<br>` で決め打ちせず、文ごとに `inline-block` で包む（docs/writing.md「画面での改行」）。幅が変わっても変な位置で切れない
- 本文の段落には当てない。段落の右端がガタガタになるため（同じ節の「本文は普通に折る」）
- 文ごとに行を変えると行が増える文（短い文・長い文・短い文の並び）は、文を短くまとめて行数も揃える（ユーザーの提案で試し、全アラートで行数が増えないことを測って確かめた）
