# Phase 31: コンソールの絞り込みの修正

## 課題

- コンソールの「警告以上」「エラーのみ」が、スクリプトの出力行にしか効いていない
- 開始の行（▶）・プロンプトと本文の行・終了の行は、どれを選んでも出たまま。
  成功した実行の行が並び、エラーの行が埋もれて「効いていない」ように見える

## 方針

- 絞り込みは実行ごとに考える。選んだレベルに当たる行（出力・失敗の終了など）を含む実行だけを残し、
  その実行の開始と終了の行を添えて、どの実行のエラーかを分かるようにする
- プロンプトと本文の行は、「すべて」のときだけ出す
- 実行に属さない行（function の知らせ・アプリのエラー）は、その行のレベルだけで決める
- 行が実行を見分けられるよう、コンソールの行に `runId` を持たせる
- 絞り込みの処理は `src/core/consoleEntries.ts` に置き、vitest でテストする
- エラー・警告の件数も、出力行だけでなく、絞り込みで当たる行（失敗・停止の終了、アプリのエラー）を数える。
  起動に失敗した実行が赤く出ているのに「エラー 0」になっていた

## 決定事項ログ

### 2026-11-23: 絞り込みは実行ごとに残す

- 当たる行がある実行は、開始・終了の行を残す。当たる行がない実行はまるごと隠す。プロンプトの行は隠す
- 理由: エラーの行だけを出すと、どの実行のものか分からなくなる
- 採らなかった案: 開始・プロンプト・終了の行にもレベルを当てて、同じ基準で絞る（単純だが、実行の見出しが消える）

### 2026-11-23: エラー・警告の件数は残し、絞り込みと同じ行を数える

- 件数の表示は消さずに残す。数える行を絞り込みと揃え、「エラー 2」なら「エラーのみ」でその2件が出るようにする
- 理由: 新しい行を追ってスクロールすると、上のエラーは見えなくなる。件数があれば、スクロールせずにエラーがあったと分かる
- 採らなかった案: 件数を消す（エラーで自動で開き、赤く出るので足りるとも言えるが、ひとまず残す）
