# Phase 39: 言語とテーマの切り替え

## 課題

- 言語のボタンが、アプリとサイトで違う。サイトは切り替え先の言語名（日本語のとき「English」）、
  アプリはいまの言語のコード（`ja`）を出す。アプリの `ja` は、いまの言語なのか押した先なのかが見て分からない
- ライト・ダークは OS の設定に従うだけで、選べない

## 方針

- 言語のボタンは、アプリとサイトで同じ形にする: 地球儀のアイコン・いまの言語名・▾。
  押すと言語の一覧（日本語 / English）を出す
  - 言語名はその言語自身で書く。国旗は使わない
  - 採らなかった案: 切り替え先だけを出すボタン。2言語なら分かりやすいが、3つ目の言語を足すと形を変えることになる
- テーマは「OS に従う / ライト / ダーク」から選ぶ。既定は OS に従う
- 記憶する単位
  - 言語: アプリ全体で1つ（いまと同じ userData の `settings.json`）
  - テーマ（アプリ）: 案件ごと。userData に案件フォルダのパスをキーにして覚える（select の `remember` と同じ）。案件のリポジトリには書かない
  - テーマ（サイト）: ブラウザの localStorage。言語は URL で分かれているので記憶しない

## 決定事項ログ

### 2026-11-28: 言語のボタンを一覧にする

- いまの言語を出し、押すと一覧が出る形にする（地球儀・言語名・▾）。アプリとサイトで揃える
- 理由: 複数の言語に広げたときの一般的な形で、▾ があれば「いまの状態」か「押した先」かで迷わない

### 2026-11-28: ライト・ダークを選べるようにし、記憶する

- アプリは案件ごとに、サイトはブラウザに記憶する。言語はアプリ全体で1つのまま

### 2026-11-28: テーマの選択肢と、案件を開いていないとき

- 選択肢は「OS に従う / ライト / ダーク」の3つ。案件を開いていない画面は、いつも OS に従う
- アプリのテーマは自分の PC にだけ覚える。キーは select の `remember` と同じ案件フォルダのパス。
  `work.launcher` に既定のテーマを書く仕組みは作らない

### 2026-11-28: ドキュメントの見本の OS を、章をまたいで残す

- 選んだ OS は sessionStorage に置き、タブを閉じるまで残す。localStorage には残さない（ユーザーの指定）
- 描く前に `<head>` のスクリプトで OS を決め、Windows 以外では描き直すまで本文を隠す。
  ビルド時の HTML（Windows の見本）が一瞬見えて切り替わるのを防ぐため。JS が無ければ隠さない
- 採らなかった案: 両方の OS の本文を HTML に書き出して CSS で出し分ける（見出しの id が重なり、目次とリンクが壊れる）
