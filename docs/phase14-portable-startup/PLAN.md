# Phase 14: ポータブル版の起動を速くする

## 課題

- Windows のポータブル版は、起動のたびに一時フォルダへ展開する。引数なしで起動してウィンドウが出るまで約9秒
  （→ phase6 の KNOWLEDGE.md）。案件リポジトリに同梱して毎日開く使い方では待ち時間が気になる
- 遅さの原因は、次のどれがどれだけ効いているかがまだわかっていない
  - `compression: maximum` の解凍
  - 展開する量（`win-unpacked` で約 390 MB。ほぼ Electron 本体）
  - 展開したファイルの Windows Defender による検査
  - Electron とアプリ自体の起動

## 方針

- **まず測る。** Windows の実機で、次の時間を比べてから手を選ぶ
  - `win-unpacked` の exe を直接起動したとき（展開なし）
  - ポータブル版を起動したとき（いまの `compression: maximum`）
  - 圧縮を変えたポータブル版を起動したとき（`normal`・`store`）
- 差が大きい（展開が主因）なら、下の案 A か B を選ぶ。小さければ Electron の起動のほうを見る

### 候補の案

| 案                | 中身                                                    | 失うもの                                     |
| ----------------- | ------------------------------------------------------- | -------------------------------------------- |
| A. 展開を1回だけ  | バージョンごとの決まったフォルダに展開し、2回目は飛ばす | 起動用の仕組みを自前で持つ・古い展開の片付け |
| B. 圧縮を弱める   | ポータブル版だけ圧縮を `normal`・`store` にする         | exe が大きくなる（同梱に重い）               |
| C. 展開済みを配る | `win-unpacked` を zip で配る                            | ファイルの多いフォルダになる                 |
| D. 見せ方を変える | 展開中にスプラッシュを出す                              | 速さは変わらない                             |

- electron-builder の portable の `unpackDirName`（展開先のフォルダ名を決める設定）で A に近いことが
  できるか、展開済みなら飛ばすかを調べる
- C は、Mac の `.app` を同梱しないと決めた理由（ファイルの多いフォルダ。→ phase6 の PLAN.md）と同じ問題がある

## 決定事項ログ

### 2026-11-15: まず Windows の実機で測ってから手を選ぶ（ユーザー決定）

- どの手がどれだけ効くかは実機でないとわからないため。作業は Windows の実機で行う

### 2026-11-15: ポータブル版は `useZip: true` にする（案 B'。ユーザー決定）

- 測ると遅さのほとんどは解凍だった（展開なし約0.9秒・いまの版約8秒。→ KNOWLEDGE.md）
- `useZip` なら設定1行で約3.7秒になる。exe は 98.5 MB から 140 MB に増えるが、同梱できる範囲
- 採らなかった案: `store`（約2.9秒だが 315 MB で同梱に重い）・`normal`（`maximum` と変わらない）・
  A（自前の起動用 exe。2回目以降は速くなるが、作って保守する手間が大きい。足りなければ次に考える）

### 2026-11-15: Defender の影響は測らずにフェーズを閉じる（ユーザー決定）

- 測るには Defender の除外を足す必要がある。`useZip` で十分に縮んだので、ここまでにする
- 案 A（自前の起動用 exe）は「次に扱う候補」へ移す
