# Phase 36 実機で確かめたこと

## 大量の出力の重さ（Mac、2026-11-24）

`examples/sample` の「大量の出力（10 万行）」を押し、終わるまでの時間と、画面が 50ms を超えて止まった間隔を測った
（requestAnimationFrame の間隔。各 2 回）。

| 実装                           | 時間   | 50ms 超の間隔 |
| ------------------------------ | ------ | ------------- |
| 旧（React で描く・5000 行）    | 3.0 秒 | なし          |
| 新・5000 行                    | 2.4 秒 | なし          |
| 新・2 万行                     | 2.4 秒 | なし          |
| 新・3 万行                     | 2.5 秒 | なし          |
| 新・5 万行                     | 2.7 秒 | 50〜90ms      |
| 新・5 万行・content-visibility | 2.8 秒 | 50〜280ms     |

- 旧実装も止まらないのは、5000 行しか持たないため。そのかわり序盤の行は消える
- `content-visibility: auto` は、行が多いほど止まる時間が長くなった（行を足すたびに末尾へ動かすので、
  見える行が入れ替わり続けるためと思われる）

## 末尾への追従が外れる

- scroll イベントは scrollTop を変えた後に遅れて届く。その間に次の出力で行が増えると、
  届いたときには末尾から離れているので、「使う人が上に戻した」と誤る（旧実装でも 10 万行で外れていた）
- 古い行を上から消すと、ブラウザのスクロールアンカーが見ている行を保とうとして、末尾から離れる。
  `.console-body` に `overflow-anchor: none` を付けて止めた
