# Phase 26: ユーザー設定の言語の表

## 課題

Phase 25 でアプリの文言とヘルプは ja / en を切り替えられるようになった。
ただ、案件の設定に書いた文字（タブ名・ボタン名・md など）は1つの文字列しか書けず、英語で表示しても日本語のまま出る。
日本と海外で共同で進める案件では、設定の文字も言語ごとに出したい。ただし完全に訳すのではなく、ベストエフォートで訳せればよい。

## 方針

- 画面に出る文字の項目は、**文字列でも、言語の表でも**書けるようにする
  - 文字列なら今までどおり、どの言語でもそれを出す（互換は崩れない）
  - `{ ja: …, en: … }` なら、表示中の言語のものを出す。無ければ**表の最初に書いた言語**を出す（空にはしない）
- 対象: `title`（案件・ページ）、`label`、`tooltip`、`confirm`、`heading`、group の見出し、選択肢の `label`、`md`、`html`
- `md` / `html` は、言語を選んだ後の値を今と同じに読む（1行で `.md` で終わればファイル、それ以外は本文）。
  長い本文は、言語ごとにファイルを分けてパスを表に書く。ファイル名から自動で探す決まりは作らない
- JS の関数には `ctx.lang` で表示中の言語を渡す
- 読み込むときに文字列へ変える（`core/load` の中で閉じる）。画面側は文字列を受け取るだけにする。
  言語を切り替えると、Phase 25 の仕組みで全部のウィンドウを読み直すので、そのとき選び直される

## 決定事項ログ

### 2026-11-22: 文字列か言語の表、足りなければ表の最初

- 文字列なら今までどおり、`{ ja, en }` なら表示中の言語に従う（ユーザーと確認）
- 表に表示中の言語が無いときは、表の最初に書いた言語を出す
- 案件の既定の言語（`config.yaml` の `lang`）は作らない（ユーザーの判断）。表の最初が実質の既定になり、設定が1つ減る

### 2026-11-22: md / html も対象にし、ファイルは表にパスを書く

- 使う場面は少なそうだが、ほかのキーと揃えて対応する（ユーザーの判断）
- 長い本文は言語ごとにファイルを分けてもらう。表の値にパスを書けるので、`setup.en.md` を自動で探す決まりは要らない
- 採らなかった案: ファイル名に言語を付けて自動で探す案。どのファイルを読むかが設定に現れず分かりにくい

### 2026-11-22: ctx.lang を渡す

- JS の関数でもメッセージを言語で切り替えられるよう、表示中の言語を渡す（ユーザーの判断）

### 2026-11-22: 表のキーは ja・en 以外も受け付ける

- 表の値が文字列でない・空の表はエラーにする（今の「文字列で書いてください」と同じ扱い）
- キーは ja・en 以外も書ける。使われないだけで、将来の言語を先に書いておける。綴りを間違えても表の最初の値が出るので、画面が空になることはない
