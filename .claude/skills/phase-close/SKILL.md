# フェーズを閉じる

**ユーザーが明示的に指示したときのみ実行する。**

## 引数

- **フェーズ番号**（任意）: 例 `3 4 5`・`6まで`。未指定なら完了済み全部が候補

## 考え方

- `design.md`・`knowledge.md` は**いまの正**。トピックごとに書き、変わったら追記せず書き換える
- `docs/archive/` は**当時の記録**。要約せずに移し、移したあとは編集しない
  （例外: リンク先のファイルが動いたときの張り替えだけ）

## 手順

1. **対象の確定**: TASKS.md が全て `[x]` で、ユーザーが完了を確かめたものだけ。
   未完了を指定されたら、その旨を伝えて判断を仰ぐ。候補の一覧を出して確定する
2. **いまの正への反映案を作る**（フォルダ内の PLAN.md・KNOWLEDGE.md を読む）
   - 決定事項ログの決定ごとに、コードや `config.md` を読めば分かるものは載せない。
     「なぜそうしたか」「採らなかった案」が後で要るものだけを `design.md` の該当トピックへ
   - KNOWLEDGE.md は、いまも当てはまる挙動・制約を `knowledge.md` の該当トピックへ。
     実測値・手順は archive に残るのでリンクで足りるなら転記しない
   - 既存の項目と食い違うものは、**古い項目を書き換える**（並べて残さない）。
     変えた理由が要るときだけ「以前は X だった（由来: Phase M）」と1行添える
   - 各項目の末尾に `（由来: [Phase N](archive/phase<N>-<slug>/PLAN.md)）`
   - HANDOFF.md は反映しない。状態が `完了` でない節が残っていたら、承認のときに示す
   - 実値（ドメイン・トークン・社内パス等）はプレースホルダーにする
3. **ユーザー承認**: `design.md`・`knowledge.md` の変更案と、移すフォルダ・張り替える参照の一覧を示し、承認まで書き込まない
4. **反映**
   - `design.md`・`knowledge.md` を直す
   - `git mv docs/phase<N>-<slug> docs/archive/` で移す。中の `../` で始まるリンクは `../../` に直す
   - `grep -rn "docs/phase<N>-" . --exclude-dir=node_modules --exclude-dir=archive` で参照を探し、
     `docs/archive/phase<N>-…` に張り替える。`design.md` に項目を作ったなら、そちらを指してもよい
   - README の表の 🚧 を ✅ に
5. **個人情報チェック**: 追記・変更箇所に実値が無いか
