# 新規フェーズ追加

## 引数

- **テーマ**（必須）: このフェーズで取り組む課題。未指定ならユーザーに確認する。
  会話で課題・方針が固まっていれば雛形に反映する。

## 手順

1. **採番**: `docs/phase*/`・`docs/archive/phase*/` のフォルダ番号と `docs/README.md` の表の番号を見て、
   最大 + 1 を `N` にする
2. **slug**: 英語 kebab-case 2〜4語（例: `overall-design` / `config-loader`）
3. **PLAN.md** を作る。判明している内容は埋め、未定は見出しだけ残す

   ```markdown
   # Phase <N>: <タイトル>

   ## 課題

   ## 方針

   ## 決定事項ログ

   ### YYYY-MM-DD: <決定の見出し>

   - （ユーザーが決めた／承認した内容と、その理由）
   ```

4. **TASKS.md** をチェックボックスで作る。末尾に共通タスクを置く

   ```markdown
   # Phase <N> タスク

   - [ ] <タスク>

   ## 共通

   - [ ] 個人情報チェック（追跡ファイルに実値が混入していないか）
   ```

   実機・OS 依存の調査を伴うなら「共通」に
   `- [ ] 実機調査で判明した挙動・制約を KNOWLEDGE.md に記録` を足す

5. **KNOWLEDGE.md・HANDOFF.md は雛形を作らない**（気づき・依頼が出た時点で作る。HANDOFF.md は `/handoff`）
6. **docs/README.md の表**の末尾に `| <N> | <フェーズ名> 🚧 | <要点1行> |` を足す。
   リンクや「進行中」の文字は置かない。セルは短く（長いと全行がその幅に揃う）
7. **個人情報チェック**: 作成・更新したファイルにメールアドレス・社名・実パス等の実値が無いか
