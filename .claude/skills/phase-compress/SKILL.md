# フェーズ圧縮

**ユーザーが明示的に指示したときのみ実行する。**

## 引数

- **フェーズ番号**（任意）: 例 `3 4 5`・`6まで`。未指定なら完了済み全部が候補

## 手順

1. **対象の確定**: TASKS.md が全て `[x]` で、README の表が 🚧 でないものだけ。
   未完了を指定されたら、その旨を伝えて判断を仰ぐ。候補一覧を出して確定する
2. **統合テキストを作る**（フォルダ内の全ファイルを読む）
   - `docs/phases.md`: `## Phase <N>: <タイトル>` の下に `- **YYYY-MM-DD** <決定と理由>`。
     タスク一覧・作業管理情報・破棄した検討の詳細は落とす
   - `docs/knowledge.md`: KNOWLEDGE.md を**要約せず**転記（見出しレベルの整形だけ）。
     フェーズ名が `##`、単体で引けるトピックが `###`、その枝が `####`
   - HANDOFF.md は統合しない（要点は回答を読んだ時点で PLAN・KNOWLEDGE へ移してある）。
     状態が `完了` でない節が残っていたら、承認のときに示す
   - 実値（ドメイン・トークン・社内パス等）はプレースホルダーにする
3. **ユーザー承認**: 追記分・削除するフォルダ・張り替える参照の一覧を示し、承認まで書き込まない
4. **反映**
   - phases.md / knowledge.md に番号順で追記（無ければ新設。冒頭に「全文を読まない。
     `## Phase <N>:` で検索して節だけ読む」と書く）
   - README の表の 🚧 を ✅ に。KNOWLEDGE.md があったら 📘 を付ける
   - `grep -rn "docs/phase<N>-" .` で参照を探し、`docs/phases.md の Phase <N>` 等に張り替える
   - フォルダを削除する（`git rm -r`。履歴に残る）
5. **個人情報チェック**: 追記・変更箇所に実値が無いか
