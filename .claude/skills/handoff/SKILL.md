# Mac ⇄ Windows のやりとり（HANDOFF.md）

## 自分はどちらか

OS で決める（`uname` が `Darwin` なら `mac`、Windows なら `win`）。

## 置き場所

- 進行中フェーズ（`docs/README.md` の表で 🚧）のフォルダの `HANDOFF.md`。1フェーズ1ファイル
- 無ければ依頼を出す側が作る。先頭は次の2行

  ```markdown
  # Phase <N> HANDOFF（Mac ⇄ Windows）

  依頼と回答のやりとり（書き方は /handoff）。新しい依頼は末尾に足す。
  ```

- 1依頼 = 1節。見出しに日時と向きを書く（向きで取り違えない。日時で同時に書いても見分けられる）

  ```markdown
  ## 2026-11-21 15:44 mac → win: <要件>

  - 状態: 依頼中
  - 関連: （PLAN.md の節や前の依頼の見出し。無ければ省く）

  ### 依頼

  - 背景: …
  - やってほしいこと: 1. … 2. …
  - 返してほしいもの: …

  ### 回答

  （受けた側が書く）
  ```

## 状態

| 状態     | だれが     | いつ                             |
| -------- | ---------- | -------------------------------- |
| 依頼中   | 依頼する側 | 節を足したとき                   |
| 回答済み | 受ける側   | 「回答」を書いたとき             |
| 保留     | 受ける側   | 進められないとき（理由を回答に） |
| 完了     | 依頼する側 | 回答の要点を docs へ移したとき   |

## 依頼を出す

1. `git pull` してから、HANDOFF.md の末尾に節を足す
2. 受ける側は会話の流れを知らない。背景・手順（コマンドはそのまま貼れる形）・返してほしいものを書く
3. HANDOFF.md だけを commit する（件名 `handoff: <要件>（依頼）`）
4. push してよいかユーザーに確かめてから push する

## 受ける

1. `git pull` し、HANDOFF.md で **→ 自分** かつ **状態: 依頼中** の節を探す（上から順に）
2. 「やってほしいこと」を実行する。依頼に無い変更（コードの修正・コミット）はしない。
   直した方がよいと気づいたら回答に書く
3. 回答を書き、状態を `回答済み` にする
4. HANDOFF.md だけを commit し（件名 `handoff: <要件>（回答）`）、push してよいかユーザーに確かめてから push する

## 回答を読む（依頼した側）

1. `git pull` し、自分が出した `回答済み` の節を読む
2. 要点を PLAN.md（決定）・KNOWLEDGE.md（OS の挙動）・TASKS.md（`[x]`）へ移し、状態を `完了` にする。
   節は消さない（フェーズを閉じるとフォルダごと docs/archive/ へ移る）

## 個人情報

- 書くときに、ユーザー名を含むパスは `~`・`%USERPROFILE%` に、名前やメールアドレスは伏せ字に置き換える
- commit・push の前に `scripts/check-personal-info.mjs` が hook で走る（.claude/settings.json）。
  止められたら書き直してからやり直す。hook を外したり、チェックを避けたりしない
- 出力は要る行だけ貼る
